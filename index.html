  • Identity

    Sybil resistance for Optimism citizenship.

    Problem Citizenship registration needed confidence in one-person-one-vote eligibility.

    Merged · op-atlas#1465 ↗

  • Production debugging

    Sponsored delegations that failed onchain.

    Problem Relayed delegateBySig transactions submitted successfully but reverted out of gas.

    Decision Trace real receipts, replace fixed limits with estimate-based buffers, and verify completion.

    Outcome The UI reports success only after the sponsored transaction actually succeeds.

    EIP-712 · gas relays · tracing

    Merged · agora-next#1514 ↗

  • Recovery

    Publishing that survives restarts.

    Problem Contract publication hit PostgreSQL bind limits and died midway through long runs.

    Decision Batch writes, persist progress, and make every step idempotently resumable.

    Outcome Interrupted runs recover instead of starting over, with live progress in the UI.

    PostgreSQL · batching · idempotency

    Merged · op-atlas#1441 ↗

2025 — now · Agora · full-time

Governance rails for Optimism, ENS & Uniswap.

Full-stack engineering across proposals, voting, delegate discovery, grants, attestations, rewards, and wallet UX for the infrastructure DAOs run on.

  • Safe multisig, first-class.

Problem

Optimism, ENS, and Uniswap needed one governance platform covering proposals, voting, delegation, grants, and identity — for different DAOs, with wallet UX spanning EOAs, Safe multisigs, and users who have never held a wallet.

Ownership

Architecture and end-to-end delivery of multi-tenant governance features: Safe-native signing, the Notifications Hub, authentication, attestation-backed eligibility, and citizenship registration.

Constraints

One codebase serving all tenants behind per-tenant flags; live DAOs that cannot break mid-vote; every change backward-compatible; security stakes measured in treasuries.

Architecture

A multi-tenant Next.js application over indexed onchain governance data; reusable SIWE JWT authentication; Safe-aware signing flows with live signer tracking; a five-channel notification platform with verification, retries, and deduplication.

Hard decisions

Replacing per-action client signatures with server-owned SIWE JWT authorization; introducing embedded wallets without touching existing relayer paths; sizing relay gas from estimates after tracing production reverts.

Outcome

Shipped across a dozen-plus tenant DAOs. 90+ merged PRs in the public repositories and two public product write-ups.

2025 · TakeAIt

A ticketing platform where coding agents are users.

Claude Code and Codex agents claim tickets, spin up isolated workspaces on private GCP VMs, execute, stream state, open pull requests — and pause when they need a human.

  • Zero-inbound security.

    Poll-only runners, rotating hashed keys, per-secret IAM, per-agent Unix users, and controlled egress.

  • Crash-resilient execution.

    Atomic work claiming, journal/replay recovery, ticket reconciliation, and redacted logs.

  • Human-in-the-loop.

    Comment-driven pause and redirection, mention-to-wake conversations, and supervision from web and CLI.

Read the case study

Problem

Coding agents are productive but ungoverned: pointed at production repositories they need isolation, auditability, and human control — or they are a liability instead of leverage.

Ownership

The platform end to end: Next.js/PostgreSQL control plane, GCP provisioning layer, and the multi-daemon Go runner runtime.

Constraints

No inbound network path to runners; secrets never at rest on execution hosts; agents crash mid-run and must recover without duplicating work; humans must be able to redirect a run in flight.

Architecture

Poll-only Go runners with rotating hashed keys and per-agent Unix users; credentials in GCP Secret Manager with per-secret IAM and temporary materialization; atomic verb-based work claiming; journal/replay recovery; SSE state streaming and automated pull-request creation.

Hard decisions

Zero-inbound polling over push; verb-based atomic claiming so concurrent agents never double-claim; journaled replay over stateless retries so partial work survives a crash.

Outcome

Claude Code and Codex agents ship reviewed pull requests daily on Agora's internal engineering — and the same workflow is how I build my own software.

2023 — present · Onchain games

Games that live on mainnets and stay up.

Sekai Glory

Led a trading-card game across 16 upgradeable contracts, real-time PvP matchmaking, and five languages — then migrated it live from Blast to Ronin.

2023–2024 · full-stack

Worked across a 55-domain Solidity monorepo, three subgraphs, and an AWS rewards engine distributing weekly ARB across the ecosystem.

Read the case study

Problem

Onchain games fail in ways web apps don't: chains get abandoned mid-product, NFT state is too slow for real-time gameplay, and randomness with money attached invites manipulation.

Ownership

Led full-stack delivery at Sekai Glory; DAO council and lead engineering at Lifeverse; full-stack and contracts at Realm — application, contracts, indexers, and infrastructure in each.

Constraints

Live players during the Blast-to-Ronin migration; matchmaking that cannot strand a queue; provable fairness for reveals and rewards; small teams owning everything.

Architecture

Hybrid state mirrored into PostgreSQL for low-latency simulation with idempotent mint and upgrade flows. UUPS contracts with Forge coverage, deterministic battle simulation with commit-reveal randomness, and subgraphs indexing live game state.

Hard decisions

Accepting reconciliation complexity for game-grade latency; rebuilding matchmaking around atomic match creation and Redis-persisted XState; migrating contracts, indexer, and app to Ronin without rebuilding the product.

Outcome

176 contracts live on Arbitrum One; the Sekai migration shipped with the game still running; the stuck-queue failure mode was eliminated rather than mitigated.
